**1. 你怎麼開始這件事？(約 1.5 分鐘)**
核心問題：你選了哪 1-2 頁、為什麼選這幾頁？工作流程是怎麼設計的？
可以引導學員談的：

- 為什麼挑這幾頁？是因為簡單、複雜、有代表性、還是想挑戰自己？
- 拿到 Figma 檔之後，怎麼跟 Claude Code 一起拆解？是先跑 plan mode、還是先用 Figma MCP 看一輪？
- 有沒有準備 CLAUDE.md、或設定任何前置條件？

想聽到的：有意識的方法選擇。學員是「亂試試看」還是「先想再做」？

**2. 過程中最關鍵的一個轉折是什麼？(約 2 分鐘)**
核心問題：什麼地方卡住了、或結果跟預期不同？你做了什麼判斷讓事情往前？
可以引導學員談的：

- Figma MCP 回傳的 code 跟你想的不一樣嗎？怎麼處理？
- 哪一個 prompt 沒效、你怎麼調整？
- 有沒有哪個時刻你決定「不該繼續往這個方向 prompt 下去」，改變策略？

想聽到的：真實的問題解決思維，而不是「Claude 都幫我做好了」這種包裝過的版本。這個面向最容易看出學員是不是真的有在駕馭工具，還是被工具拖著走。


**3. 如果重新做一次、或下次接到類似任務，你會做什麼不一樣？(約 1.5 分鐘)**
核心問題：這次經驗對你未來作為設計師的工作流程，留下什麼？
可以引導學員談的：

- 哪一個環節你會用完全不同的方式處理？
- 你對 Figma MCP / Claude Code 的「能做什麼、不能做什麼」，有什麼新的認知？
- 這次經驗會改變你之後跟工程師合作的方式嗎？

想聽到的：把工具使用內化成自己的工作方法。能講出這層的學員，才算是真的「學會」這堂課，而不只是學會操作。
